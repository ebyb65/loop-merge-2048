# LevelPlay migration and verification

The old Android bridge loaded Unity Ads bidding placements directly and failed with
`adMarkup is missing; objectId is missing`. A bidding placement needs an actual
mediation auction. This branch uses LevelPlay's Android SDK and Unity Ads adapter.

## Remaining account setup

The Unity Ads bidder is **not yet linked**. LevelPlay's UnityAds account setup
requests a Unity Monetization Stats API key and Organization Core ID; the Unity
API management page showed that the stats API key has not been created. Creating
and sharing a credential with LevelPlay is an account-access change and must be
approved. Configure and verify the Unity Ads bidder and its placement mapping in
LevelPlay before assuming Unity Ads can serve. LevelPlay shows another network on
the ad units; its presence alone does not prove a Unity Ads integration or fill.

Unity organization settings currently report no developer website and an invalid
app-ads URL. The repository seller file includes the Unity DIRECT entry shown
by the dashboard while retaining the existing Google entry. This draft does not
prove that the file is served from the developer website root or that Unity can
verify it. After publication, configure the developer website and verify Unity
can read the correct root-level app-ads.txt. The dashboard also lists additional
resellers; check Unity’s current guidance before adding those.

The original banner request was never implemented by the old Capacitor plugin.
This branch addresses rewarded and interstitial ads. Banner integration needs a
LevelPlay banner ad unit and a verified layout before it can be enabled.

## Android build and test

The pull-request workflow builds an unsigned debug-signed APK without reading
release-signing secrets and uploads it as `Drop2048-LevelPlay-test-APK`. Wait for
the build to pass; this project is generated by CI and local JS tests alone do
not validate an Android build. Do not publish the debug APK.

Before interacting with ads on a device, use LevelPlay's test-device setup and
the relevant network's test configuration. LevelPlay's app key and ad-unit IDs
are not automatically test IDs; a debug build alone does not force test ads.
See https://docs.unity.com/en-us/grow/levelplay/sdk/android/integration-testing.

After configuring a test device and the bidder:

1. Install the debug APK and confirm LevelPlay initializes in the on-screen log.
2. Confirm both formats report successful load callbacks. If a request fails,
   capture its exact error; no-fill and configuration failures are distinct.
3. Finish a rewarded ad and verify the intended reward is granted exactly once.
4. Skip an ad, fail an ad, and double-tap; confirm no unearned or duplicate reward.
5. Confirm a new rewarded ad loads after completing the previous one and that
   an interstitial shows at the expected time without overlapping a rewarded ad.
6. Verify the ad network using LevelPlay test tools and the network mapping.

The LevelPlay bridge resolves its `load*` calls when the load **starts**; this
controller waits for `loaded` or `loadFailed` events before showing an ad.
`showRewarded()` returns whether the reward callback fired. Failed or skipped
ads don't grant the in-game reward. SDK test mode, live ad delivery, account
approval, privacy and consent must be checked before any production release.
The current controller sends `gdprConsent: false`; this is not a complete
consent management flow for all jurisdictions or networks.

Run `node --test tests/ads-controller.test.cjs` for the local mocked lifecycle
checks. Passing those tests does not prove the Android SDK or network delivers ads.
